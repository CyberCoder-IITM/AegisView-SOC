═══════════════════════════════════════════════════════════════════════════

Every device on a network has a unique "fingerprint" based on how

    DeviceProfile(

      packet_size_std: float,
      avg_ttl: float,

FEATURE 3 — CRYPTOGRAPHIC PACKET INTEGRITY CHAIN
═══════════════════════════════════════════════════════════════════════════

This is what makes AegisView "court-admissible forensics ready."
Every packet gets a SHA-256 hash, and each hash includes the 
previous hash — creating a blockchain-style tamper-evident chain.
If anyone modifies captured data, the chain breaks.

Create backend/analysis/integrity_chain.py:

  Class PacketIntegrityChain:
    genesis_hash = sha256("AEGISVIEW_GENESIS_BLOCK").hexdigest()
    chain: list[ChainEntry] = []
    
    ChainEntry(
      index: int,
      timestamp: ISO8601,
      packet_hash: str,      (sha256 of packet dict as JSON)
      previous_hash: str,
      chain_hash: str,       (sha256 of packet_hash + previous_hash)
      is_valid: bool
    )
    
    Method: add_packet(packet_dict) -> ChainEntry
      packet_hash = sha256(json.dumps(packet_dict, sort_keys=True))
      previous_hash = chain[-1].chain_hash if chain else genesis_hash
      chain_hash = sha256(packet_hash + previous_hash)
      Append ChainEntry, return it
    
    Method: verify_chain() -> ChainVerification
      Walk entire chain, recompute all hashes
      Return: ChainVerification(
        total_entries: int,
        valid_entries: int,
        tampered_indices: list[int],
        integrity_status: "INTACT"|"COMPROMISED",
        verification_timestamp: ISO8601
      )
    
    Keep only last 1000 entries in chain (deque)
    
    Routes:
      GET /api/chain/status → chain length, integrity_status, 
                              last_verified timestamp
      GET /api/chain/verify → run full verify_chain(), return result
      GET /api/chain/latest → last 10 ChainEntries

FEATURE 4 — PREDICTIVE THREAT FORECASTING ENGINE
═══════════════════════════════════════════════════════════════════════════

Uses time-series analysis to predict where the threat level 
will be in the next 5 minutes. Shows a forecast line extending 
beyond the current chart — exactly like what Recorded Future sells.

Create backend/analysis/forecaster.py:

  Class ThreatForecaster:
    Maintains rolling time series of threat scores:
      threat_history: deque(maxlen=360)  (one per 5s = 30 min)
    
    Method: add_datapoint(score: int, timestamp: datetime)
    
    Method: forecast(horizon_steps: int = 12) -> Forecast
      (12 steps × 5s = 60 second forecast)
      
      Algorithm — Triple Exponential Smoothing (Holt-Winters):
        alpha = 0.3  (level smoothing)
        beta = 0.1   (trend smoothing)  
        gamma = 0.1  (seasonal smoothing, period=12)
        
        Implement from scratch (no statsmodels needed):
          level[0] = threat_history[0]
          trend[0] = mean(diff of first 12 points)
          For each t: update level, trend using EWM formulas
          Forecast = level[-1] + (h * trend[-1])
        
        Add confidence intervals:
          upper_bound = forecast + (1.96 * rolling_std)
          lower_bound = max(0, forecast - (1.96 * rolling_std))
        
      Return Forecast(
        predictions: [{step, timestamp, value, upper, lower}],
        trend_direction: "RISING"|"FALLING"|"STABLE",
        predicted_peak: int,
        predicted_peak_time: ISO8601,
        alert: str | null  
          (e.g. "⚠ Threat level predicted to reach CRITICAL 
           in approximately 3 minutes")
      )
    
    Route: GET /api/forecast → current Forecast object
    Updates every 5 seconds as new threat scores come in
